# Human Verify 2 Fast — Retrieval @5

ประเมินผล Retrieval ที่บันทึกอยู่ใน `../human_verify_2_fast/` ใหม่ครบทั้ง 5 Config
Config ละ 50 ข้อ รวม 250 ผลรายข้อ โดยทุก Config ใช้คำถามและ Gold ชุดเดียวกัน

## ผลสรุป

| Config | จำนวนข้อ | Hit@5 | Recall@5 | MRR@5 |
|---|---:|---:|---:|---:|
| Vector | 50 | 0.600 | 0.320 | 0.359 |
| Graph | 50 | 0.660 | 0.357 | 0.343 |
| Agent + Vector | 50 | 0.860 | 0.590 | 0.728 |
| Agent + Graph | 50 | 0.940 | 0.663 | 0.786 |
| Text-to-Cypher | 50 | 0.640 | 0.417 | 0.452 |

ตารางและ `summary` ใน YAML ปัดทศนิยม 3 ตำแหน่งตามรูปแบบเดิมของโครงการ
ส่วน [summary.csv](summary.csv), [summary.json](summary.json) และ
[per_query_metrics.csv](per_query_metrics.csv) เก็บค่าที่คำนวณก่อนปัดทศนิยม

## วิธีคำนวณ

ต่อคำถามหนึ่งข้อ ให้ `R5 = top_chunk_ids[:5]` ตามลำดับในไฟล์ต้นฉบับ และให้
`G` เป็นเซตของ `gold_chunks` ทั้งหมดของข้อนั้น

- Hit@5 = 1 เมื่อ `R5` มี Gold อย่างน้อยหนึ่ง chunk มิฉะนั้นเป็น 0
- Recall@5 = จำนวน Gold ที่พบใน `R5` / จำนวน Gold ทั้งหมดใน `G`
- Reciprocal Rank@5 = `1 / rank` ของ Gold ตัวแรกใน `R5` ถ้าไม่พบเป็น 0
- MRR@5 = ค่าเฉลี่ย Reciprocal Rank@5 ของทั้ง 50 ข้อ
- Hit@5 และ Recall@5 ในผลสรุปเป็นค่าเฉลี่ยรายข้อเช่นกัน (macro average)
- ถ้าผลเดิมมีน้อยกว่า 5 chunk ใช้ทั้งหมดเท่าที่มี ถ้าไม่มี chunk ให้ทั้งสามคะแนนเป็น 0
- คงลำดับเดิม ไม่มีการจัดอันดับใหม่หรือเอารายการซ้ำออกก่อนตัด 5 รายการ
  การนับ Gold ที่พบใช้เซตตามวิธีเดิมใน `eval_scripts/evaluate_new_agent.py`

นี่เป็นการคำนวณคะแนนจากผลเดิม (post-hoc) ไม่ได้รัน Retrieval หรือเรียก LLM ใหม่
จึงไม่ใช่ผลทดลองที่เปลี่ยน `top_k_chunks=5` แล้วรันระบบตั้งแต่ต้น
สำหรับ Agent ใช้ลำดับชุดหลักฐานสุดท้ายที่บันทึกใน `top_chunk_ids`
ซึ่งไม่ได้ยืนยันว่าเป็นอันดับความเกี่ยวข้องจากคะแนนกลางเดียวกันระหว่าง Config

## ข้อมูลที่เก็บไว้

- YAML ชื่อเดิมต่อท้าย `_at5.yaml` ทั้ง 5 ไฟล์มี `top_chunk_ids` ที่ตัดเหลือไม่เกิน 5
  และคำนวณ `hit`, `recall`, `reciprocal_rank` ใหม่ พร้อม `evaluation_k: 5`
- `source_retrieval` เก็บรายการ chunk และคะแนนเดิมของแต่ละข้อ
  ส่วน `source_summary` เก็บสรุปเดิมทั้งหมด
- `evaluation` ระบุวิธีคำนวณ ไฟล์ต้นทาง SHA-256 และเวลา UTC ที่สร้างผล
- ข้อมูลอื่น เช่น `final_answer`, `synthesis_trace`, `measurement`, เวลา และ token
  เก็บจากรอบเดิมทั้งหมด คำตอบอาจอ้างหลักฐานนอก 5 รายการแรก
  จึงใช้เป็นคะแนนคำตอบ เวลา หรือค่าใช้จ่ายของการรัน @5 ไม่ได้
- ไฟล์ต้นฉบับใน `human_verify_2_fast` ไม่ถูกแก้ไข

## คำนวณซ้ำ

จากโฟลเดอร์รากของโครงการ ใช้ Python ที่ติดตั้ง PyYAML:

```bash
python benchmark/human_verify_2_fast_at5/recompute.py
```

สคริปต์ตรวจจำนวนข้อ ID ซ้ำ Gold ว่าง ความตรงกันของคำถามและ Gold ระหว่าง Config
และความตรงกันของคะแนนรายข้อเดิม ก่อนสร้างผลในโฟลเดอร์นี้
