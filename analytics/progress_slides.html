02 · Retrieval Stack

เครื่องมือค้นข้อมูลที่มีในโค้ดตอนนี้

Vector Search

ค้นด้วยsemantic similarity จาก embedding ของ chunk — baseline สำหรับคำถามเชิงหัวข้อใน 10-K

Graph Search

ใช้โครงสร้างความสัมพันธ์ใน KG ผ่าน Personalized PageRank เหมาะกับคำถาม multi-hop

Hybrid Search

รวม vector + graph ด้วย RRF เพื่อเก็บทั้ง topical match และ relational signal

Financial Tool

ดึง snapshot ตัวเลขจากFinnhub เช่น revenue, margin, P/E, quote ล่าสุด ใน schema เดียวกับ retriever อื่น

News Tool

ดึงข่าวล่าสุดของบริษัทใน corpus พร้อม recency score, cache option และโหมด headline / full body

ทุก tool คืนผลในรูป `{chunk_id, text, ticker, fiscal_year, section, score}` เพื่อให้สลับใช้หรือ route ผ่าน agent ได้ง่าย

02 · Retrieval Stack

Graph Search — Personalized PageRank

query → seed entities → PPR บน graph → collapse aliases → map กลับเป็น chunk; จุดแข็งคือเชื่อมคำถามไปหาหลักฐานที่ไม่ได้ใช้คำเดียวกัน

02 · Retrieval Stack

สิ่งที่เพิ่มเข้ามาใน graph pipeline

  • Query Expansion — ให้ LLM เติม entity / ticker ที่แฝงอยู่ในคำถามก่อน embed
  • Query-to-Triple seeds — หา triple ที่ใกล้กับคำถาม แล้วใช้ทั้ง head และ tail เป็นจุดตั้งต้น
  • Damping 0.7 — ปรับให้เหมาะกับ sparse KG และลด hub leakage
  • SYNONYM collapse — รวม alias ของ entity ก่อนสะสมคะแนนกลับมาที่ chunk

`graph_search()` ตอนนี้ไม่ใช่ PPR ตรงๆ อย่างเดียว แต่เป็น pipeline เต็ม query → expansion → triple seeds → PPR → alias collapse → chunk ranking

04 · Agent & Demo

LangGraph agent ตอนนี้อยู่จุดไหน

มีแล้ว
  • `plan_node` แตกคำถามเป็น 1-3 subqueries
  • `tool_select_node` ใช้ tool calling route ไปยัง `vector / graph / financial / news` (ยังไม่ expose `hybrid`)
  • `build_agent()` ประกอบ workflow `plan → tool_select → execute → observe → reflect → synthesize`
ต้องต่อเพิ่ม
  • `execute_node`, `observe_node`, `reflect_node`, `synthesize_node` ยังคืนค่าเปล่า
  • ยังไม่มี multi-round loop, memory accumulation และ citation merge
  • ยังไม่ใช่ end-to-end agent ที่ใช้งานจริงใน production flow
ขั้นถัดไป

งานที่เหลือเพื่อให้คำว่า "Agentic" สมบูรณ์

  • D1 ต่อ `execute → synthesize` ให้ agent เรียก tool แล้วสรุปคำตอบหลายแหล่งได้จริง
  • D2 เพิ่ม loop สะท้อนผล retrieval เมื่อหลักฐานยังไม่พอ
  • E ประเมิน answer quality ของ agent เต็มรูปแบบทั้งไทยและอังกฤษ
  • F2 ถ้าต้องรองรับหลายปีเชิงตัวเลข ค่อยแยก financial backend ไป SQL / XBRL

สรุป

Corpus, retrieval และ real-time tools พร้อมแล้ว
งานหลักที่เหลือคือเชื่อม agent loop ให้ครบ end-to-end
